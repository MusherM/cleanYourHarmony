# cleanYourHarmony

English: [README_en.md](README_en.md)

鸿蒙手机设置工具，提供 macOS 原生界面（SwiftUI）和 Windows 原生工程（WinUI 3），共用本地固定路线执行器。正常运行无需 Agent、模型或网络。

## 桌面应用

左侧显示通过 hdc 读取的手机型号、系统版本与四类设置；右侧为包含全部 20 项的连续列表，四类名称作为列表内的小标题，侧栏点击可跳转到对应位置。每行只保留“是否执行”复选框。勾选后按清单默认目标执行：主页切换为简洁主页，其余项目关闭；取消勾选则保持原状。勾选不会立即修改手机。

初次打开默认勾选全部 20 项并使用清爽化目标。切换分类保留编辑；未选项目保持原状。点击“执行所选项目”后按实际页面合并处理，实时显示结果。停止时先核验已发生的修改并恢复勿扰，异常退出后的任务可续跑。通知关闭会影响该应用的正常通知。

- 目标平台：macOS 13.5+（arm64/x64），Windows 11 x64。
- 当前本机已构建 macOS arm64 开发包；Intel Mac、Windows 安装与业务验收尚未完成。源码和构建入口不等于已发布安装包。
- 运行时内置 Node.js 24.22.2（官方 macOS 二进制最低要求 13.5）、hdc、USB 动态库和执行脚本；Windows 发布使用自包含 .NET / Windows App SDK。
- 手机仍需开启 USB 调试并授权电脑。锁屏凭据由用户输入；应用不修改锁屏配置。
- 进度与截图：macOS 为 ~/Library/Application Support/cleanYourHarmony/runs；Windows 为 %LOCALAPPDATA%/cleanYourHarmony/runs。证据仅保存在本机。
- 不使用自动更新、遥测或云端执行。没有整机回滚功能；停止任务不会撤销已经验证的业务设置，仅恢复本次临时改变的勿扰。

### 构建与打包

构建主机需要 Node.js 24+；macOS 需要 Swift 工具链，Windows 需要 .NET 8 SDK、Windows SDK、WinUI 构建工具和 Inno Setup 6。终端用户不需要这些开发工具。

先从官方 OpenHarmony / HarmonyOS SDK 准备目标平台的 toolchains 目录，再封装固定运行时。Node 下载地址及 SHA-256 锁定在 packaging/runtime-lock.json，下载缓存保存在 build/downloads。

```sh
# macOS arm64，本机已安装 SDK 时可省略 --hdc-dir
node packaging/prepare-runtime.mjs --platform darwin-arm64 --hdc-dir /path/to/toolchains
node packaging/build-macos.mjs --arch arm64 --dmg

# macOS Intel，必须使用 x64 hdc 和 USB 库，不能复制 arm64 工具
node packaging/prepare-runtime.mjs --platform darwin-x64 --hdc-dir /path/to/x64/toolchains
node packaging/build-macos.mjs --arch x64 --dmg

# 离线行为测试，不会操作手机
node --test scripts/runner.test.mjs scripts/desktop.test.mjs
```

Windows 构建主机执行：

```powershell
node packaging/prepare-runtime.mjs --platform win32-x64 --hdc-dir C:\SDK\toolchains
pwsh -File packaging/build-windows.ps1
```

产物位于 dist/macos-arm64、dist/macos-x64 或 dist/windows-x64。build 与 dist 不纳入版本管理。未传发布参数时，仅生成开发包；macOS 使用临时签名，不能当作已公证的公开发行包。

公开发布前，必须审核具体 hdc 二进制及依赖的再分发条款，不能仅凭 hdc 源码许可证判断 SDK 二进制可分发。prepare-runtime.mjs 的 --hdc-manifest 接受包含 platform、source、redistributionReviewed、files（文件名到 SHA-256）的已审核清单。没有清单时记录为仅供本地开发，发布模式拒绝继续。

macOS 发布使用 --release，并配置 CYH_SIGN_IDENTITY、CYH_NOTARY_PROFILE（已有钥匙串配置名）；打包器执行签名、公证和 stapler 校验。Windows 使用 build-windows.ps1 -Release -CertificateThumbprint <已有证书指纹>。凭据不写入仓库。Windows 可通过 -DriverDirectory 纳入经过审核的签名驱动，清单另需 hardwareIds 和 inf；安装器仅对匹配硬件且驱动异常的设备请求提权安装。未提供经审核驱动时不会擅自替换系统驱动；首次连接兼容性必须在干净 Windows 环境验证。

不同平台的 SDK 工具与签名证书未纳入本仓库；这是公开发布的外部前置条件。当前不能声称无需这些资产即可从零产生签名发行包。

### 本地通信与兼容性

原生界面通过标准输入／输出 JSON Lines 调用 scripts/desktop-host.mjs。协议见 [desktop/PROTOCOL.md](desktop/PROTOCOL.md)。工作线程串行执行设备命令，主线程处理停止请求；设备轮询不会与执行任务并行。

首版适配基线为现有 HarmonyOS 7 语义路线。未知弹层、入口变化或禁用控件不会用旧坐标猜测。重新开启的设置可能出现额外确认页面，尚未逐项完成所有设备的双向实测。旧 schemaVersion 1 进度不支持直接作为 GUI 任务续跑；有待恢复勿扰时应先按原版本流程恢复，再创建新任务。

[operations.json](operations.json) 是 Agent 的操作清单，主要做这些事：

- **浏览器更清爽**：换成简洁主页，关闭搜索榜单和搜索热词。

不会删除浏览记录、注销服务，也不调整自动播放等使用习惯；清单排除的停车、日程、出行、快递等实用服务不作为关闭目标。已经符合目标的设置不会反复切换，每项结果都会留证。

面向鸿蒙手机的清爽化操作清单：减少广告、信息流、营销消息和主动内容推荐，保留正常信息展示与实用服务；每项结论附实机证据。

## 可选：使用 Agent 处理命令行及异常

把本仓库交给能操作电脑和已连接手机的 Agent 即可。电脑端的工具检查和缺失工具安装由 Agent 完成；你只需连接手机，并按提示开启开发者选项、USB 调试和信任电脑。锁屏密码、设备授权及系统权限提示由你本人处理。仅能对话、不能操作电脑和设备的 Agent 无法代为执行。

在仓库目录中启动 Agent，发送以下指令即可开始：

```text
请先阅读 AGENTS.md、README.md 和 operations.json，
对当前连接的鸿蒙手机执行 operations.json 中 default_selected 为 true 的项目；
默认直接执行全部 20 项，不设可选项，不询问是否纳入。若连接多台设备，先让我选择目标。
自行检查并复用电脑端工具；缺少 hdc、UI Tree/GUI 操作工具或 Node.js 18+ 时，
从官方来源自动安装适合当前系统的版本并验证，不要把安装任务交回给我。
仅在需要我输入密码、确认系统权限、操作手机授权或环境限制确实阻止安装时告知具体阻塞。
若检测不到手机或设备未授权，先按 README 的连接指引逐步指导我开启开发者模式、USB 调试及信任电脑，再重新检测。
优先通过 UI Tree 定位和读取状态，仅在必要时使用视觉能力，并在报告中区分。
已满足目标的项目标记为无需修改；通知应用搜索无精确匹配时标记为未找到；其他无法定位、控件禁用或修改后验证不通过的项目标记为执行失败。
用户体验改进计划保留在清单中，无法关闭时按执行失败处理。
按实际页面合并操作，执行后立即核对状态、截图并持久化进度；同页可共用截图。
仅对修改过的页面就地重进一次验证，禁止全部执行后再从头复查或补拍。
执行前记录勿扰状态并临时开启，结束或异常时恢复原状态，记录恢复结果。
直接用文字汇报各项成功、失败及失败原因；单列未找到和未完成项，说明勿扰恢复结果。
历史验证记录只用于参考，不能代替本次设备验证。
```

Agent 优先使用仓库脚本执行固定路线，遇到未知页面、遮挡或控件变化时再处理异常。每次执行仍需根据本次设备证据验收，历史记录不能替代。

### 脚本执行入口（供 Agent 使用）

先准备好工具，再运行以下入口。脚本默认只打印计划，只有 `--execute` 会操作手机。

```sh
node scripts/run.mjs --plan
node scripts/run.mjs --execute
```

默认全部 20 项，不弹出通知选择题。多设备时使用 `--device <本次设备ID>`；`--hdc <可执行文件路径>` 可复用已有 SDK。脚本按 16 个实际页面分组，沿最近父页导航，每次修改后即时截图，修改页只重进一次。

同页连续读取在 500 毫秒内复用本次快照；点击、滚动、应用启动、截图或超时后重新读树。相邻应用的通知设置复用搜索页，仍逐项核对应用名称、前台页面和开关状态。正常路径完全由脚本执行，无需模型逐步判断。

展开屏设置采用双栏时，顶层入口在左侧导航栏查找和滚动，顶层页面间切换直接复用可见左栏，避免系统返回退出设置；详情页以最后一个标题栏核对，通知搜索使用详情标题栏。应用内容区域之外的系统多任务按钮不视为遮挡；与内容重叠的其他窗口仍会阻止操作。浏览器启动等待可识别内容，目标控件最多等待 20 秒，短暂浮层在超时范围内等待消失。精确识别到“置顶显示通知合并到优先通知”的功能说明时，只正常返回关闭一次；其余持续存在的授权或引导弹窗由 Agent 处理。

CLI 新任务结果保存在 `dev/device-run/runs/<本次时间>_<运行ID>/`，包含 `progress.json`、截图和命令计时。只有全部业务项目有证据才报告完成；勿扰准备与恢复结果单独记录。设备独占锁防止同一脚本并发操作，执行期间其他 Agent 也不能操作该设备。

失败后先检查进度和已有证据，定位原因并修复，再运行 `node scripts/run.mjs --execute --resume <原证据目录>`。已完成页不重放；设备、版本或清单改变时拒绝复用。恢复范围是同次任务续跑，不是把旧证据当作新的验收。强制杀进程后先确认进程已退出，检查 `/tmp/cyh-device-*.lock/owner.json`，再由 Agent 清理对应的过期锁；不得删掉仍在使用的锁。

通知应用可能已被卸载。确认搜索页、搜索词及结果区正常且等待结束后仍无精确匹配时，记录 `not_found`（未找到）并留证，继续后续项目；不把未找到推断为已卸载或已关闭。续跑跳过本次已记录的未找到项。最终报告单独显示“未找到”；仅有缺失项时运行结果为 `completed_with_missing`，退出码为 0，实际业务失败仍为 2。遮挡、加载、设备命令或页面异常仍按执行失败处理。

脚本使用正常 UI 路径，不绕过禁用控件。未知页面或无法唯一定位时记录失败，不用旧坐标猜测。报告从现场证据生成，不再走一遍手机流程。

### 执行规则

1. 先检查并复用已验证的工具链；缺少 hdc、UI Tree/GUI 操作能力或 Node.js 18+ 时，由 Agent 从官方来源自动安装适配当前操作系统与架构的版本，再验证工具可运行及实际设备操作能力。不要要求用户手动找下载地址或安装命令，不重复安装已有可用工具；遇到凭据、系统授权或环境限制时说明具体阻塞。随后枚举当前设备、核对系统和应用版本，单设备串行执行。先按选中项目生成执行计划，按应用及实际页面合并，复用相邻页的共同父路径；不要机械地逐条从首页重新导航。默认全部 20 项，不为通知项目询问选择。
2. 使用 `operations.json` 的 `path` 和 `locator` 作为预设语义路线。缓存可复用的入口、选择器、页面标识与适用版本，不缓存整棵旧 UI Tree、节点序号或绝对坐标作为下一次点击依据。首次到达、导航或滚动、点击引发状态变化、出现遮挡后刷新树；页面标题出现不等于控件加载完成，应等目标状态可读取后再操作。页面未变时复用本次树，一次提取所有所需信息，避免反复启动命令分析同一个文件。
3. 已验证的导航可在一次工具调用内串行完成“取树—匹配当前页及唯一目标—点击—检查下一页”，只返回精简结果；有失败立即停止该路线。减少模型往返，不省略当前页面、应用、前台弹层、目标唯一性及状态检查。坐标由当次 bounds 计算。文本相同的搜索框不等于搜索结果，后台弹层里的标题不等于当前页面；应用启动也不等于返回根页。
4. 读取目标控件的 `checked`、`enabled`，显式解析布尔值（字符串 `"false"` 不是真值）。已经满足则记录无需修改、当场截图，不强制重进；禁用或有歧义时保存证据并报告失败。仅修改用户选定项目，每次修改后刷新状态；失败不得直接重放 Toggle。
5. 采用“当前页处理—状态验证—截图落盘—更新进度—离开”的顺序。同页能同时展示多个项目时共用一张图；要滚动时先保存即将离开视口的结果。只有发生修改的页面，在本页面批次结束时从最近父页重进一次，验证本页已修改项目并保存重进证据；不要逐个开关重进，也不要全部操作后再从头复查或补拍。
6. `screenshot.group` 是证据分组，不是强制合并执行页。F01/F02 的子页操作后立即保存子页证据，正常返回父设置页时再保存 G03 合照；父页摘要不能替代子页开关验证。截图失败时留在当前页处理，不能为补图重新切换开关。图像仅覆盖实际可见的项目。
7. 首次设备操作前创建 `dev/<主题>/evidence_<北京时间>/progress.json`，记录本次设备/版本、授权项目、当前页、每项修改前后状态、截图相对路径、采集时间、SHA-256 和重进验证状态；每完成一页立即持久化，不依赖聊天记忆。截图必须确认生成成功、文件非空且来自本次采集，不能读到旧文件就算成功。中断后先读取进度，仅处理未完成项；跨会话恢复先确认设备和现状，历史记录不自动升级为当前验证。
8. 执行前读取并记录勿扰原状态；原为关闭时临时开启并确认，原为开启时保持。结束、失败或可捕获的中断均走恢复步骤，只撤销本次改变并确认原状态已恢复；强制终止时无法保证清理，必须在进度中保留待恢复标记，下次继续时优先处理。原状态读不出时不猜测；开启或恢复失败单独记录，不宣称成功。不修改勿扰的日程、例外或通知权限来替代临时勿扰。勿扰不保证挡住全部横幅，输入法、系统弹窗与应用内浮层仍须检测。
9. 页面等待使用有超时的状态检查，到达即继续；避免多层固定 sleep 叠加。已验证的工具能力、应用入口和解析器在本轮复用，不反复探测。新解析器先用已保存的树离线验证，不能边修解析器边反复操作手机。
10. 每次失败先检查现有输出、当前树和截图，定位原因后最多进行一次针对性恢复；仍失败则记录该项并继续独立项目，不循环从头跑。命令退出码、业务成功标记和预期页面分别核对；管道使用 `set -o pipefail`，不能用 `head/tail` 掩盖失败。最终报告直接引用已保存证据，不为生成报告再走设备流程。

截图用于留证，保存图片本身不要求视觉模型。只有树无法提供必要的目标或状态时，才使用视觉推理，并明确记录该回退。固定路线由脚本执行，未识别的页面交由 Agent 处理；脚本执行结果与实测耗时以本次 progress.json 和证据为准。

### 检测不到手机时

Agent 应先确认设备工具可用，再检查连接结果；工具缺失时自行安装并验证，无法运行时先定位和修复电脑端环境。设备列表为空或设备未授权时，向用户逐步提供以下指引，等待用户完成后重新检测，不能直接跳过所有操作：

1. 解锁手机，使用支持数据传输的 USB 线连接电脑，并保持亮屏。
2. 打开手机“设置”，搜索“软件版本”；也可进入“关于手机”或以设备名称显示的入口，找到“软件版本”或“软件版本号”。连续快速点击 7 次，按提示开启开发者选项。若要求锁屏密码，由用户自行输入；若提示重启，确认并等待重启后解锁。
3. 进入“设置 → 系统 → 开发者选项”（名称可能为“开发人员选项”，也可在设置中搜索），开启“USB 调试”，确认手机上的开启提示。
4. 保持手机解锁；在“允许 USB 调试”等电脑授权弹窗中，核对当前电脑后点击“允许”。如有“始终允许此电脑”选项，由用户自行决定是否勾选。若未弹出，拔插数据线后再次观察手机。
5. Agent 重新枚举设备，确认设备在线且可读取新的 UI Tree，再开始执行。仍无法连接时，依次尝试更换数据线、直连电脑 USB 接口，并检查电脑端工具或驱动；清楚区分未检测到、未授权和工具故障。

入口和重启流程参考华为官方的[开发者选项说明](https://consumer.huawei.com/cn/support/content/zh-cn02842747/)及[USB 调试连接说明](https://consumer.huawei.com/cn/support/content/zh-cn00698619/)，具体名称以手机实际界面为准。此处是连接故障引导，不代表本项目已经验证过所有设备的首次授权流程。
